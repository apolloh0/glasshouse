# Decision log (ADR-lite)

Append-only. One entry per decision that a future reader could not infer.

**D1 — Hand-rolled lexer + recursive-descent parser for Phase 0.** The design
plan names Lezer as the editor grammar. Phase 0 has no editor, and the spike's
risk is evaluator performance/determinism, not parsing. Lezer (with an
indentation external tokenizer) arrives in Phase 1; a conformance test will
keep the two in sync, and we will evaluate then whether to make Lezer the only
parser.

**D2 — Display-list equality replaces pixel equality.** "Pixel-identical" in
the design plan is operationalized as byte-identical serialized display lists.
Stronger (no rasterizer ambiguity), CI-friendly (no canvas needed in tests).

**D3 — PRNG is mulberry32.** Small, fast, seedable, good enough for learner
programs; its 32-bit state lives in EngineState so history snapshots capture
it. Changing the algorithm invalidates all goldens — don't.

**D4 — rect is anchored left/top.** One convention only. (An earlier plan
draft showed a bottom-anchored example; top-left won for consistency with the
stage's y-down coordinate system.)

**D5 — Setup drawing = staticOps.** Setup runs once; its ops are prepended to
every frame's ops. A program with no frame/event blocks is a static picture.
Setup cannot read `pointer` or assign.

**D6 — No `group(...)` transform blocks in Phase 0.** They exist for the
Phase 3 transform visualization; the spike doesn't need them.

**D7 — Node ids are per-parse pre-order integers.** Stability across *edits*
(GumTree-style matching) is Phase 1+. Phase 0 only requires: same source
string, same ids.

**D8 — `°` and `deg` are interchangeable angle suffixes.** The degree sign is
the canonical display form; `deg` exists because keyboards.

**D9 — Colors are packed to 0xRRGGBB integers at parse time.** One float64
carries a color through the trace store's numeric columns.

**D10 — Phase 1 extends this repo; no second repo.** The editor consumes the
engine's contracts directly; splitting packages before Phase 2 would only
add publish friction.

**D11 — Two parsers, one truth.** Lezer parses for presentation (syntax
highlighting, tolerant trees while typing); the hand-rolled parser stays the
sole semantic authority. A token-level drift guard in `tests/lezer.test.ts`
keeps them honest. Revisit at Phase 4 if editor features start wanting real
structure from Lezer.

**D12 — The Lezer grammar is line-oriented.** It does not model indentation
blocks; nesting comes from the semantic parser. Indent-tracking external
tokenizers are the hairiest part of Lezer grammars, and highlighting needs
tokens, not blocks.

**D13 — Annotations are an overlay type, not display ops.** `AnnotationOp`
never enters a display list, the trace, or the goldens — the program's
output stays exactly what the program drew.

**D14 — The generated Lezer parser is committed.** `src/editor/gen/` is
regenerated by `npm run grammar` and checked in, so clone → typecheck works
without a build step. The .grammar file is the source; never hand-edit gen/.

**D15 — `diagnosticsFor` reports at most one problem.** Chalk's parser stops
at the first error anyway, and one clear sentence beats a cascade for a
learner. Multi-diagnostic recovery is a possible Phase 2+ upgrade.

**D16 — Two id layers.** Per-parse pre-order ids (D7) remain the engine's
only identity; traces and goldens never change meaning. StableIds are an
editor-side layer minted by `IdTracker` so panes survive re-parses. Nothing
under `src/engine` may ever consume a stable id.

**D17 — GumTree-lite matching, honesty first.** Two passes (fingerprint
anchors top-down, same-kind positional recovery bottom-up under matched
parents, virtual root for top-level items). Invariants: total, injective,
kind-preserving, deterministic. A full honest reset always beats a doubtful
match — a wrong attribution in the timeline is the worst failure mode.

**D18 — Iteration grids cap at 64 columns.** `truncated: true` signals the
cut; the first 64 iterations are shown. Summarization (sparkline collapse)
is Phase 3's aggregate work, not a Phase 2 scroll bar.

**D19 — Ghost alphas pinned.** Onion-skin: 0.30/0.18/0.08 by frame distance,
max 3 per side, returned in paint order (faintest first, before-frame ahead
of after-frame at equal alpha). Trails: oldest-first slices at a stride.
Ghosts never enter display lists, traces, or goldens (same principle as D13).

**D20 — Scrub semantics are post-state.** Position `step` shows the world
after step `step` completes; the op cutoff includes ops with
stepIndex <= step. One rule, no off-by-one debates.

**D21 — Setup is traceable.** `runSetup` gains an optional mode (default
"fast", same evaluator code path per invariant 3) and returns its trace when
instrumented; `Session.traceSetup()` exposes it. Static pictures are the
essay's home turf — the scrubber must work there. staticLayer op stepIndex
values refer to the setup trace.

**D22 — Still no browser automation in Phase 2.** Scrubber, timeline, and
ghost logic are pure and vitest-tested; the studio remains thin glue behind
a manual script. Playwright buys little at this thinness and costs CI a
browser download; revisit when direct manipulation lands (Phase 4).

**D23 — Transforms move to Phase 4.** The plan put `group` blocks and the
transformed-coordinate-frame visualization in Phase 3; they move to open
Phase 4 instead. Reasons: they are a LANGUAGE extension (parser, evaluator
transform stack, trace surface) while everything else in Phase 3 is pure
decoding of data Phase 0 already records; they pair naturally with Phase
4's creation tooling (on-stage handles live in transformed frames); and
freezing the language through Phase 3 freezes the goldens. Phase 3's exit
gate stays purely about data visibility.

**D24 — Inputs are state.** `Session.inputsAt(k)` exposes recorded frame
inputs (passthrough to History). The state panel shows pointer position and
buttons with the same machinery as vars.

**D25 — No new tracing for Phase 3.** Every expression completion already
carries its typed value (Phase 0). Cells and hover values are decoded
lazily per focused row. Refines T7's write-row encoding: strIdx = var name,
nodeId = the writing assign/state-decl, value in (valueTag, a, b); string
values put their intern index in `a` (strIdx is taken by the name).

**D26 — Cell kinds and zoom pinned.** Cells are value | ops | mark per the
classification in `src/flow/cells.ts`. Zoom has ONE threshold: >= 28 px
cell width shows figures, below shows plots. Thumbnails render at 24×18.

**D27 — Thumbnails are exact.** Computed from real display ops by uniform
bounding-box fit (`thumbnailFit`), capped at 1:1, never magnified, never
re-drawn approximations. What the cell shows IS what the program drew.

**D28 — Diff pairs by (kind, sourceNodeId, occurrence).** stepIndex is
excluded from comparison. A moved shape is `changed`, never removed+added —
motion is change.

**D29 — Sparkline geometry pinned.** Point i of n: x = i*(w-1)/(n-1)
(single point centers), y = (h-1) - (v-min)/(max-min)*(h-1), flat series at
(h-1)/2, nulls gap. Shared by the state panel and row plots.

**D30 — A definition parameter's span points at its binding name.**
`Definition.params` (CONTRACT, ast.ts) stores `{name, span}` where `name` is
the call label (pinned by tests/parser.test.ts and fingerprint.ts). Chalk
params are Swift-style `label: bindingName` (`to house(at: base, ...)`), and
the binding name needs a home the type doesn't give it. Rather than edit the
CONTRACT type, the parser points each param's `span` at the binding-name
token, so the evaluator (and Phase 1 hover) recover it with
`source.slice(span.start, span.end)`. Deliberate trade: spans become
semantics for this one field. If a later phase wants an explicit `bind`
field, that's a contract-change entry then.
*Reviewed and approved; expect promotion to an explicit `bind` field as a
contract change at Phase 4/5 design (the "teach this" gesture needs it).*

**D31 — The step/row accounting model (frozen by the first goldens).**
One trace row per: expression completion, statement completion, state/local
WRITE (state decls, assignments, and loop-counter binds each iteration —
nodeId = the declaring/assigning/loop node), and callEnter/callExit around
USER definition calls only (builtins complete as one expr row). Every row
consumes one step index in BOTH modes (ops serialize stepIndex, so fast and
instrumented must number identically); ops carry the emitting call's
completion index. Write rows precede their statement's completion row
(post-state scrubbing shows the write applied). Definitions, frame blocks,
and event blocks are containers, not steps. Param binds are NOT write rows
(callEnter marks the boundary; revisiting this would change every golden).
The 5000-iteration stress program lands at exactly 50,007 rows/frame.
*Reviewed and approved; verified against the Phase 2/3 test expectations.*

**D33 — Pass-2 matching requires equal callees for call nodes.** In
matchPrograms pass 2 (same-kind positional recovery), `call` nodes
additionally require prev.callee === next.callee; all other kinds keep the
kind-only rule. Rationale: kind-only slots let a total line rewrite
(circle(...) -> rect(...)) re-badge an unrelated statement's call with a
carried stable id — invariant-legal but against D17's honesty rule, and
Phase 4 attaches heavier state to stable ids. Pinned by
tests/match-tightening.test.ts (circle->rect rewrite is drop+mint for the
call and its arguments; the statement SLOT — the ExprStmt — may still
carry). Pass 1 is unaffected (fingerprints already include callees).

**D35 — Phase 4 splits into 4a and 4b.** 4a (this scaffold): the group
language extension, completions + previews, palette, literal-level drags —
everything creation-shaped that needs no provenance. 4b (provenance,
inversion, drag disambiguation) is designed only after 4a lands, against
the evaluator as-built and its measured instrumented headroom. Rationale:
4b is the project's research-grade core; quarantine the risk, and spec
against reality, not stubs.

**D36 — `group` semantics (Chalk v1.1).** Syntax: `group(move:, rotate:,
scale:, around:):` + indented body, ≥1 arg, only those labels; statement
position anywhere. rotate takes angle or number-of-degrees; scale uniform
and positive. Matrix: T(move)·T(around)·R(deg)·S(s)·T(-around), nesting
parent·child, positive rotation clockwise on screen (y-down/canvas).
Transforms apply EAGERLY at emit — ops carry world coordinates; display
list format, serializer, renderer, diff, bounds untouched; radii and
stroke widths scale. Nonzero rotation lowers rect to two exact triangles
(ABC+ACD, one step index) and makes ellipse a friendly diagnostic. D31
extension: group = one statement completion row after its body; args are
expr rows re-evaluated per execution; container for executedInFrames, row
for executedStatements/iterationGrid. No new trace surface — the viz
derives matrices from traced arg values. Eager application also makes the
transform part of each coordinate's affine chain, which is exactly what
4b's inversion needs.

**D37 — `bind` promoted to a field (closes D30).** `Definition.params`
gains `bind?: string`; the parser populates it; `span` keeps pointing at
the binding token for D30-era readers. Hover reads `bind`.

**D38 — Completion and preview rules.** Candidates: draw builtins + paper
(full default-arg calls; stdlib dflt else FALLBACK_DEFAULTS by type, both

definitions (args `0`; previews may error and are listed anyway),
CONSTRUCT_TEMPLATES. previewFor = parse + setup + ≤1 NO_INPUT frame,
session-isolated, ChalkErrors as data, deterministic.

Point handles only where both coordinates are literals; computed

**D42 — Trig is rounded to the 1e-9 grid (P4b-T0).** Math.cos/sin differ by
last-bit ULPs across platform libms, so rotation goldens were machine-
pinned (the pinwheel golden generated on macOS arm64 fails byte-equality
on Linux x86 — found in review). Both trig sites (the evaluator's affine
helper and flow/transform.matrixFor) round cos/sin to 1e-9 before use;
downstream IEEE arithmetic is portable, so rotated coordinates are
bit-identical everywhere. 1e-9 is invisible at pixel scale. Pinwheel's
golden regenerates once; the four trig-free goldens must not move.

**D43 — Provenance is post-hoc, affine, and honest.** Chains (value =
Σ coeff·literal + c) are reconstructed from the existing trace by a pure
bottom-up AST walk — no evaluator, tracer, or format change; instrumented
cost untouched. Rules: literals are unit terms; state vars, counters,
random, pointer are opaque constants at their traced values; definition
params CHASE their call-site argument chains through callStackAt (the
house drag depends on it); products with terms on both sides go opaque;
division scales only by opaque divisors. Cross-frame chains (through
state) are explicitly out of scope — a later phase if ever.

**D44 — Group matrices are constants in chains.** A world coordinate is
affine in the shape's literals with the active matrices' entries as
numbers. Dragging a transformed shape edits the shape, never the angle;
angle adjustment stays with the 4a angle widget (a rotation handle is
possible future work).

**D45 — Candidate policy.** Per-axis solve from anchor chains; opaque axes
lock (reported, no edits); one candidate per nonzero-coeff term,
to = from + Δ/coeff; rank |Δlit| ascending, ties by source order; pair
cross-product capped at 6 by total |Δ|; a both-axes literal joins a pair
only if its two solutions agree within 1e-9 — skip, never average.
Application uses D39 snapping/formatting and must keep IdTracker at
0 fresh / 0 dropped. Correctness oracle: prediction consistency — apply,
re-run, land where pointed (every inversion test ends with it).

**D46 — ANCHOR_SOURCES pinned.** circle/ellipse→center, rect→(left,top),
line→from, triangle→a; lowered-rect triangles map corner `a` to
(left, top). 4b's only scalar attr is circle radius ("size").

**D48 — (coeff, id) is THE canonical chain term order (unified, reviewed).**
The house attrChain ground truth (provenance.test.ts) pins a rect anchor's
y-chain as `[{lit40,-1},{lit220,1}]` — the SUBTRACTED term (`-h`) before the
term it adjusts (`base.y`) — which lit-id-ascending never produces (a.x stays

already coeff-ascending, and dropping a term is order-independent.

**D49 — Drag candidates are exact 2x2 solves per literal pair.** A drag
candidate that edits two literals solves the 2x2 system
[xc(Lx) xc(Ly); yc(Lx) yc(Ly)]·[δx;δy] = [dx;dy] (Cramer), so re-running
lands the WORLD anchor exactly at (drag) before snapping — the coupling
through a group's rotation matrix is cancelled, not approximated. A singular
pairing (det ~ 0) is SKIPPED, never averaged. A literal feeding both axes
joins only if its single-δ solutions agree within 1e-9 (D45), else skipped.
Per-axis single-literal solving (to = from + Δ/coeff) is the degenerate case
when one axis is opaque, zero-delta, or the pair is decoupled. Ranking is
unchanged: total |Δlit| ascending, ties by source order, cap 6. The oracle
(apply, re-run, land where pointed) is what these serve; the pinwheel blade
proves it through a live rotation.

**D50 — Gestures are output-preserving, verified by the display oracle.**
Every abstraction gesture (Phase 5) is checked by
serializeDisplayList(before) === serializeDisplayList(after) over setup and
a 60-frame same-seed run for animated programs. A gesture that changes a
pixel is a bug. Second pin: statements the gesture did not rewrite keep
their stable ids (fresh/dropped confined to the rewritten region);
unchanged code is span-spliced, never re-printed. The studio re-runs the
oracle before committing so a failing transform is never shown.

*AMENDED (2026-07-13, reviewed) — the visual oracle is `serializeVisual`,
not `serializeDisplayList`.* The full serialization embeds `sourceNodeId`
and `stepIndex`; any statement insertion renumbers parse-time ids and step
counters, so a byte-identical full serialization is UNSATISFIABLE by any
correct gesture (proof: a static program's `state` decl must precede the
shape that reads it — naming `20` shifts sourceNodeId 4→6, stepIndex 8→11,
picture unchanged). `serializeVisual` (render/displayList.ts) emits bg +
every geometric/color/stroke field in draw order, excluding ONLY those two
provenance columns; it still fails on a reordered draw, changed op count,
or any moved coordinate/color (pinned by tests/visual.test.ts). The oracle
is now TWO co-required clauses, both asserted for every gesture: (1)
`serializeVisual` equality over setup + the frame run (the picture holds),
and (2) the untouched-identity pin (IdTracker, Gate AB) covering provenance
for code the gesture didn't touch. Neither alone is sufficient.
`serializeDisplayList` is unchanged — goldens, linking, and scrubbing keep
the full form.

**D51 — nameThisNumber emits a `state` decl.** Chalk has one binding
concept; a named constant is a state var (bonus: it shows in the state
panel at once). Placement is AFTER the last existing state decl (else after
paper, else line 1) so evaluation order — and thus the picture — cannot
shift. The literal's use site becomes the name.

**D52 — connectNumbers candidate policy.** Name litA, replace it, then rank
litB: equal values -> [same]; ratio k=B/A with 2k an integer ->
[scale (name*k), offset (name+d)]; otherwise [offset]. Offsets read
"name + d" (or "name - |d|"). Every candidate is oracle-clean by
construction; the learner disambiguates by seeing the previews.

**D53 — repeatThis affine unification.** k>=2 consecutive siblings unify iff
structurally identical up to NUMBER leaves (colors/angles/strings/bools/
names/callees exact; first mismatch named in a friendly reason). Each
number position must be constant or affine in the 1-based index
(v_j = base+(j-1)*step); non-affine spacing declines with the real gaps.
Structural-up-to-numbers reuses fingerprintNode with number leaves masked
— not a fresh tree walk.

**D54 — teachThis relativizes to a point parameter.** Selected statements
become `to name(at: p): ... end` with `bind` = "p" (D37's field, finally
spent). The first shape's literal anchor (ANCHOR_SOURCES) is the origin;
body point literals rewrite to (p.x+dx, p.y+dy), dx==0 folding to p.x. The
selection becomes `name(at: (anchor))`. Requires a literal anchor on the
first shape; scalars stay literal (compose with nameThisNumber to
parameterize a size).

**D55 — openThisUp inlines and folds.** The inverse of teach: a call to a
user definition inlines its body with args substituted for binds; a point
literal substituted into a member access FOLDS (p.x, p:=(60,80) -> 60) so
no member-on-literal is ever emitted. v1 requires literal/bare-name args
(richer args decline in learner words). Pinned identity:
open(teach(S)) draws byte-identically to S.

**D56 — Synthesis style is pinned in one place.** synth.ts is the sole
source of emitted text: numbers via showValue, points "(x, y)", two-space
indent, one space after label colons, and canonical simplified affine forms
(step 0 -> "B"; base 0 step 1 -> "i - 1"; base 0 -> "(i - 1) * S"; base==step
-> "i * S"; else "B + (i - 1) * S"; negative step uses " - (i - 1) * |S|").
It covers only what gestures emit; it is not a general pretty-printer.
